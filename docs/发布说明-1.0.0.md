## 构建与安装

```powershell
cd D:\work\project
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
. .\scripts\env.ps1
.\gradlew.bat assembleRelease bundleRelease lintRelease testDebugUnitTest

# 新设备首次安装：
adb install .\app\build\outputs\apk\release\app-release.apk
adb shell am start -n com.example.jianji/.MainActivity
```

以后升级正式版可使用 `adb install -r`，前提是包名相同、签名相同且 versionCode 不降低。未来版本继续递增 versionCode。

**旧 debug 版与正式版的签名不同，无法直接覆盖安装。** 如果设备中有真实记账数据，请保留旧应用；不要直接卸载或清除数据。本版无导出恢复功能，卸载会丢失账本；可先在另一台设备安装正式版。没有在本次发布中自动卸载、替换设备上的应用或迁移数据库。

## 签名保管与实现思路

首次发布生成的私钥位于项目 `.signing/jianji-release.jks`，凭据位于根目录 `keystore.properties`。两者均被 `.gitignore` 排除。请将它们单独安全备份，并限制访问；不要将凭据或密钥随 APK 分发。丢失私钥会影响相同签名的后续升级，重装开发环境时不要重新生成并替换现有密钥。

Gradle 从本地凭据文件读取发布签名，release 不使用 debug 密钥。`preReleaseBuild` 先校验签名配置，缺少配置时明确失败，防止误交付未签名包。`keystore.properties.example` 仅含占位符。R8 使用 Android 默认优化规则与库自带 consumer rules；保留源码行号并归档 mapping，用于分析混淆后的崩溃。
