# Android 开发环境配置

日期：2026-10-23。适用 Windows x64 / PowerShell 5.1 或 7；项目根目录为 `D:\work\project`。本项目使用本地可移植工具链，不要求全局修改 JAVA_HOME 或 PATH。

## 1. 固定版本与安装位置

| 组件 | 版本 | 位置 / 说明 |
|---|---|---|
| JDK | Azul Zulu OpenJDK 17.0.20.1 x64 | `.tools/zulu17.68.203-ca-jdk17.0.20.1-win_x64` |
| Gradle | 8.11.1 | `.tools/gradle-8.11.1`，正式构建使用 Wrapper |
| Android Gradle Plugin | 8.9.2 | 由 Gradle 下载 |
| Kotlin / Compose 编译插件 | 2.1.20 | 由版本目录固定 |
| Compose BOM | 2025.04.01 | 统一 Compose 组件版本 |
| Android SDK Command-line Tools | 19.0 | `.tools/android-sdk/cmdline-tools/19.0` |
| SDK Platform | Android 15 / API 35 | `.tools/android-sdk/platforms/android-35` |
| Build Tools | 35.0.0 | `.tools/android-sdk/build-tools/35.0.0` |
| Platform Tools / adb | SDK 仓库稳定版 | `.tools/android-sdk/platform-tools`，实际版本见验证记录 |
| 最低系统 / 目标系统 | API 26 / API 35 | 支持 Android 8.0 起 |
| Android Studio（可选） | Meerkat 2024.3.1 或兼容 AGP 8.9 的更高稳定版 | IDE 需另行安装，不影响命令行编译 |

这是一组固定的开发基线，不代表各组件最新版本。上架前检查 [Google Play 目标 API 要求](https://developer.android.com/google/play/requirements/target-sdk) 并整体升级相关 SDK / AGP / Gradle，不能只随意提高单个版本。

初次联网安装与构建建议预留至少 10GB 可用空间，安装模拟器另预留 10～20GB。Gradle 和 Maven 首次缓存较大，构建耗时受网络影响。

## 2. 安装与激活

```powershell
Set-Location D:\work\project
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-android.ps1
. .\scripts\env.ps1
.\scripts\doctor.ps1
```

安装脚本下载 JDK、Gradle、Android 命令行工具，校验安装包，解压到 `.tools`，安装 API 35 / Build Tools / adb，生成 `local.properties` 和官方 Gradle Wrapper。SDK 安装会显示许可提示；如已阅读并接受相关许可，可显式使用 `-AcceptAndroidLicenses` 用于自动化安装。

Gradle 官方下载缓慢时：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-android.ps1 -UseGradleMirror
```

此选项使用华为云 Gradle 镜像，校验值仍来自 Gradle 官方 SHA-256。首次生成 Wrapper 时将记录所选下载源；若 Wrapper 已存在，脚本不会覆盖它，切换源需编辑 `gradle/wrapper/gradle-wrapper.properties` 的 distributionUrl，保留 distributionSha256Sum。Google Maven 与 Maven Central 依赖仍从官方仓库下载。

如果 SDK Manager 在下载阶段长时间无进展，可增加 `-DownloadSdkArchives`。该模式仍先处理 SDK 许可，再通过 curl 从 Google 官方源下载已固定版本的 SDK 压缩包、核对官方 SHA-1 后安装。本机采用此模式，避免 Java 下载阶段停滞；普通 SDK Manager 更新能力仍保留。

脚本可重复运行：复用校验通过的安装包和现有工具；SDK manager 负责检测已安装组件。脚本只修改当前进程环境，重新打开终端需要再次 dot-source `env.ps1`。不要提交 `.tools`、`local.properties`、构建产物或签名密钥。

校验信息集中在 `scripts/toolchain.json`：JDK 和 Gradle 使用 SHA-256；Android 命令行工具使用官方 repository XML 提供的 SHA-1，并通过 HTTPS 官方源下载。升级工具时同步版本、URL 和可信校验值，不能关闭校验绕过错误。

## 3. 构建与检查

```powershell
. .\scripts\env.ps1
.\gradlew.bat --version
.\gradlew.bat assembleDebug lintDebug
```

- 安装包：`app/build/outputs/apk/debug/app-debug.apk`。
- Lint HTML：`app/build/reports/lint-results-debug.html`。
- 当前骨架无业务单元测试；后续添加测试后执行 `testDebugUnitTest`。
- 真机或模拟器准备好、且添加仪器测试后执行 `connectedDebugAndroidTest`。
- 首次构建需联网；依赖完整缓存后可使用 `--offline`，但它不能补齐缺失依赖。

Lint 将警告视为错误。版本升级提示应先判断兼容性再处理，不能为了通过检查关闭所有规则。财务逻辑需按开发文档补充测试，本阶段构建成功只证明工具链和工程配置可用。

## 4. Android Studio 配置（可选）

1. 从 [Android Studio 官方网站](https://developer.android.com/studio) 安装稳定版，选择 Open 打开 `D:\work\project`。
2. Settings → Build, Execution, Deployment → Build Tools → Gradle，将 Gradle JDK 指向本项目 `.tools` 下的 JDK 17。
3. SDK Location 指向 `D:\work\project\.tools\android-sdk`，与 `local.properties` 保持一致。
4. 为共用已下载依赖，将 Gradle user home 配置为 `D:\work\project\.tools\gradle-user-home`；菜单位置随 IDE 版本可能变化。也可先在载入 `env.ps1` 的终端启动 IDE，使其继承项目环境。
5. Sync Project with Gradle Files，选择 app 模块和设备运行。若升级 IDE，不接受自动升级 AGP 的提示后立即提交；先验证全套构建和测试。

本次不自动安装图形 IDE、不启动可见窗口。命令行工具足以构建 APK；编辑、预览和日常断点调试建议使用 Android Studio。

## 5. 真机运行与模拟器准备

优先使用 Android 8.0+ 真机，打开开发者选项和 USB 调试，连接 USB 并在手机上允许当前电脑调试。Windows 可能需要设备厂商 USB 驱动。

```powershell
. .\scripts\env.ps1
adb devices -l
# 设备状态必须为 device；unauthorized 时先在手机上确认。
adb -s <设备序列号> install -r .\app\build\outputs\apk\debug\app-debug.apk
adb -s <设备序列号> shell am start -n com.example.jianji/.MainActivity
```

若有多个设备，始终使用 `-s` 明确目标。不要直接清空用户设备数据。APK 为 debug 签名的开发准备版，只展示骨架界面。

需要模拟器时，在 Android Studio Device Manager 中创建 Pixel 系列设备，建议先用 API 35 Google APIs x86_64，再增加 API 26 兼容性设备。检查 BIOS 虚拟化和 Windows Hypervisor Platform，启用 Windows 功能可能需要管理员权限及重启。本次没有修改 BIOS/虚拟化配置，也未下载大型模拟器镜像。

可选命令行安装：

```powershell
sdkmanager 'emulator' 'system-images;android-35;google_apis;x86_64'
avdmanager create avd --name Jianji_API35 --package 'system-images;android-35;google_apis;x86_64' --device pixel_6
& "$env:ANDROID_HOME\emulator\emulator.exe" -avd Jianji_API35
```

## 6. 常见问题

| 现象 | 原因与处理 |
|---|---|
| java/adb 无法识别 | 当前终端未载入 `env.ps1`，或安装未完成；先运行 doctor |
| Unsupported class file / JDK 不匹配 | 检查 `JAVA_HOME` 和 IDE Gradle JDK 都指向 JDK 17 |
| SDK location not found | 运行 setup 生成本机 `local.properties`；移动工程后重新运行 setup |
| SDK licenses not accepted | 运行 `sdkmanager --licenses` 阅读并接受需要的许可 |
| Gradle 下载过慢 | 使用已提供的镜像选项，保持官方校验值；不要使用无校验二进制 |
| Maven 无法连接 | 检查网络/代理；在用户 Gradle 配置中设置代理，不把账号密码写入仓库 |
| 环境内限制联网 | 在允许联网的终端执行安装/首次构建；离线模式需要已有完整缓存 |
| adb unauthorized / 列表为空 | 检查手机授权、数据线、USB 模式和厂商驱动 |
| 模拟器无法启动 | 检查 CPU 虚拟化、Hypervisor 和可用内存；可先用真机 |
| local.properties 路径错误 | 安装脚本自动使用斜杠并转义盘符，避免手写反斜杠转义问题 |

## 7. 本地自动化测试

载入 `scripts/env.ps1` 后执行：

```powershell
.\gradlew.bat assembleDebug lintDebug testDebugUnitTest
```

业务规则使用 JUnit，数据库和 Compose 流程使用 Robolectric，在 JVM 上模拟 Android API 28。界面测试启用原生图形模式以正确测量字体。首次执行会下载测试依赖和 Android 运行库，耗时与网络有关；运行库缓存在项目 `.tools/robolectric-maven`，Gradle 依赖缓存在 `.tools/gradle-user-home`。默认下载源为官方 Maven Central，完整缓存后可离线复用。

测试 HTML 报告：`app/build/reports/tests/testDebugUnitTest/index.html`；Lint 报告：`app/build/reports/lint-results-debug.html`。它们不替代真机或模拟器验收。
