# 简记 0.2.0 实现与验证记录

日期：2026-10-23。本文记录 P0 实现；产品与详细设计中的 P1 不是本版已交付功能。

## 功能与入口

| 入口 | 已实现行为 |
|---|---|
| 明细 → 记一笔 | 金额、8 个内置类型、1970 年至今天的消费日期、200 字符内备注；字段校验；未保存离开确认 |
| 明细 → 消费详情 | 查看完整记录、编辑、确认删除；取消删除不会修改数据库 |
| 明细筛选 | 本月、上月、全部历史、自定义范围、类型多选、备注字面搜索；30 条分页、按日分组、完整筛选结果汇总 |
| 统计 | 总支出、笔数、自然日日均、分类环形图、金额条形图、分类金额及百分比；按类型进入相同日期范围的明细 |
| 设置 | 跟随系统、浅色、深色主题，DataStore 保存选择；说明本机存储和备份状态 |

本版仅人民币支出；无收入、账户登录、联网同步、自定义类型、预算、备份恢复和删除撤销。无演示账单。卸载或清除应用数据会丢失账本。

## 实现结构与调用流程

| 源码 | 职责 |
|---|---|
| `JianjiApplication.kt` | Application 和 AppContainer，创建数据库、仓库与设置依赖 |
| `domain/Models.kt`、`Rules.kt` | 领域模型、日期范围、金额解析、备注校验、命令摘要、统计计算 |
| `domain/ExpenseRepository.kt` | 写入接口和 SaveExpenseUseCase |
| `application/ExpenseQueryService.kt` | 分页明细、完整汇总、类型统计的查询接口 |
| `data/LedgerDatabase.kt` | Room 表、索引、外键、LedgerDao；schema 导出到 `app/schemas` |
| `data/RoomExpenseRepository.kt` | 初始化类型、事务写入、幂等校验、乐观锁、SQL 筛选和聚合 |
| `data/SettingsRepository.kt` | DataStore 主题偏好 |
| `ui/ViewModels.kt` | 加载状态、筛选状态、草稿、提交状态、失败重试与 SavedStateHandle 恢复 |
| `ui/JianjiApp.kt` | Compose 主题、导航、依赖注入与启动初始化 |
| `ui/ExpenseScreens.kt`、`StatisticsScreen.kt`、`SettingsScreen.kt`、`Components.kt` | 页面、图表、日期/类型选择和错误状态 |

保存路径：Compose 表单 → ViewModel → ValidateExpenseUseCase → SaveExpenseUseCase → Repository → Room 事务。金额经 BigDecimal 精确转换为整数分，拒绝超限和超过两位小数的输入。事务内检查 dataEpoch、operationId 摘要和 revision，随后一起写入消费、回执和变更序号；任一步失败整体回滚。成功后 Room 的 Flow 通知明细和统计刷新，无需手动累加维护统计金额。

查询路径：页面筛选 → ViewModel Flow → ExpenseQueryService → 参数化 SQL → PagingData/汇总 Flow → Compose。每日小计来自全部匹配记录，避免只汇总已加载的一页。备注使用 `instr` 字面匹配，`%` 和 `_` 不会扩大查询范围。

统计按稳定类型 ID 聚合；金额计算保持整数或 BigDecimal，仅绘图比例转浮点。环形图和条形图共享同一统计快照。超过 8 类的统计计算支持前 7 类加其余类型；当前界面只有 8 个内置类型。空数据不绘制虚假的扇区。

## 与设计的落地差异

- DAO 合并为 LedgerDao；写入命令通过一个事务入口处理；用 AppContainer 手动注入，未引入 Hilt。
- 分类图表使用 Compose Canvas 和进度条，不依赖第三方图表库；类型标识使用颜色和汉字。
- 中文界面文本目前主要在 Compose 中；多语言资源拆分留待国际化阶段。
- 当前只有 schema v1，没有生产数据库升级场景；未来改表必须提供迁移，未启用破坏性重建。
- 保存草稿和不可变提交命令使用 SavedStateHandle；这不是用户主动保存的草稿箱，也不承诺强制停止后的草稿恢复。
- 没有 HTTP 接口。接口指本机 Kotlin、Room 和 Android API；无需服务器配置。

## 本轮问题修复

- Kotlin 对互相引用的 Flow 属性无法完成类型推导，导致编译失败；为筛选 StateFlow 和类型集合显式声明类型，消除推导循环。
- 提交结果未知时如果继续允许修改表单，重试可能与原提交不一致；保留不可变待确认命令，并锁定输入，重试原 operationId。
- 编辑页加载失败后可能留下可操作表单；增加加载失败状态和重试入口，在取得数据集标识与原记录前禁用保存。
- 分页内自行插入日期标题可能在跨页时重复；统一由 Paging 的 insertSeparators 根据相邻记录生成标题。
- “记一笔”按钮缺少无障碍名称：Material 3 扩展浮动按钮清除了内部文字语义，图标又设置为无描述，读屏与语义测试无法识别。为图标添加“记一笔”描述，并通过名称操作按钮的界面测试验证。
